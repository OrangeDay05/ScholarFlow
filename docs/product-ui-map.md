## 1. UX 目标与边界

### 1.1 产品心智

用户进入系统后应感知到的是“论文项目工作台”，而不是普通聊天机器人。页面持续回答五个问题：

1. 我当前在哪个论文项目、哪个章节？
2. 项目现在处于哪一步？
3. 系统读取了哪些要求和材料？
4. 当前判断来自用户材料、AI 归纳，还是尚缺信息？
5. 本次操作是否创建了新版本，引用是否能回到上传原文？

### 1.2 M1–M2 共用原则

- 中文学术 SaaS，专业、清晰、可信、克制，桌面端优先。
- 保留当前“研序 / ScholarFlow”品牌、深绿与纸张感视觉方向，后续视觉修改通过 M1 审核。
- 支持中文、英文和双语项目；界面语言切换不等同于项目目标语言。
- 五种创建方式地位平等，用户可从任一入口开始，之后继续补材料。
- 项目诊断卡只有“已确认”状态才能作为正式写作上下文。
- 诊断卡未确认时，正式章节写作必须被阻断；不能只提示后仍允许执行。
- 用户每次运行 Skill 前必须明确选择本次允许读取的材料。
- 前端只展示六个产品级 Skill，不展示内部 Skill 名称。
- AI 生成、修改、恢复和备用模型重试都必须显示“将创建新版本”。
- 检查类 Skill 只输出报告，不静默改写正文。
- “用户上传原文可核对”不得表述为“已通过外部数据库验证”。
- 用户侧只出现“导出 DOCX”；不得出现 PDF 或 Markdown 导出入口。
- M1、M2 所有非真实能力必须有持续可见的“演示数据 / Mock”标识。

### 1.3 明确排除的入口

M1、M2 的用户端、管理员端、空状态、更多菜单、设置、弹窗和占位卡片中均不得出现：

- 会员、套餐、积分、充值、支付、订单、退款、优惠券；
- 项目共享、邀请成员、多人协作、共用账号；
- AI 写作风险检测、AI 率；
- 公开来源相似度、专业查重；
- 自动投稿；
- 外部付费论文获取；
- Z-Library、安娜的档案等未经授权来源；
- 学校教师端；
- PDF 或 Markdown 导出；
- 复杂运营、客服、营收或利润后台。

## 2. 当前页面基线

当前 `/` 是单路由、内存状态驱动的可点击演示，已具备：

- 工作台侧栏、顶部栏和最近项目；
- 五种创建卡片；
- 通用创建弹窗；
- 项目诊断概览与确认按钮；
- 左目录 / 中正文 / 右助手的三栏编辑器；
- 版本、证据和 Word 导出入口的视觉雏形；
- 桌面与窄屏基础响应式样式。

M1 可复用其品牌、颜色、卡片、诊断区和三栏布局，但不能把以下现状视为已满足门控：

| 当前现状 | M1 必须修正 |
|---|---|
| 工作台、项目和编辑器都在 `/` 内切换 | 建立本文冻结的真实路由；刷新与直接访问不丢失当前页 |
| 只有一个通用创建弹窗 | 五种入口分别呈现与材料类型匹配的表单骨架 |
| 可以从工作台直接进入编辑器 | 未确认诊断卡时进入阻断态，不能运行正式章节写作 |
| 右栏只有“续写、润色、逻辑检查、引用建议”四个快捷动作 | 改为六个产品级 Skill；具体操作放入所选 Skill 内 |
| 显示“12 篇已验证原文” | 改为“12 篇已上传并解析（演示）”或“可回到上传原文核对” |
| 页面未持续标注 Mock | 所有演示项目、任务、解析结果、证据和系统状态增加 Mock 标识 |
| 创建、保存、任务和导出主要以 Toast 模拟 | M1 显示状态骨架；M2 才形成可点击状态流 |
| 没有认证页和管理员页 | M1 补认证骨架；管理员四页在 M2 完成可点击原型 |

### 3.1 页面职责

| 页面 | 用户核心问题 | 主操作 |
|---|---|---|
| 登录 / 注册 | 如何进入自己的工作区？ | 账号密码登录或注册 |
| 项目工作台 | 现在应继续哪个项目、哪一步？ | 继续项目、新建项目、搜索筛选 |
| 创建方式选择 | 我目前拥有什么材料？ | 选择五种入口之一 |
| 创建表单 | 需要提交什么信息或文件？ | 填写、加入上传队列、保存草稿 |
| 项目概览 | 项目整体进展和风险是什么？ | 前往诊断、目录、材料或编辑器 |
| 诊断卡 | 系统对项目的理解是否准确？ | 修改、补材料、确认或取消确认 |
| 目录 | 论文结构是否合适？ | 编辑、排序、确认章节结构 |
| 编辑器 | 当前章节如何写、改、查和留证？ | 编辑、保存版本、运行 Skill、查看证据 |
| 材料 | 系统有哪些可读取材料？ | 查看解析状态、分类、删除或重试 |
| 文献库 | 已上传文献能支持什么？ | 查看元数据、矩阵和原文位置 |
| AI 任务 | 当前任务执行到哪一步？ | 查看、取消、重试或打开结果 |
| 导出检查 | 当前论文是否适合导出？ | 处理警告后导出 DOCX |

## 4. 简易管理员信息架构

管理员使用独立导航框架，不与普通用户工作区混排，只保留四页：

```text
简易管理员
├─ 用户管理
├─ 项目与文件
├─ AI 任务
└─ 模型与 Skill
```

| 页面 | 展示内容 | 允许操作 | 明确不包含 |
|---|---|---|---|
| 用户管理 | 用户标识、账号状态、最近登录、失败原因 | 冻结、解冻 | 套餐、余额、订单、共享成员 |
| 项目与文件 | 项目归属、文件类型、处理状态、存储信息 | 查看详情和错误 | 内容运营、项目协作 |

普通用户页面只展示六个产品级 Skill 名称。管理员详情可为排障显示内部入口、版本和实际模型，但不能把“已安装”标为“产品已实现”。

## 5. 路由冻结与里程碑边界

- `:projectId` 使用 Mock 时固定为 `demo`，M3 后替换为真实 ID。

- 状态演示可使用 `?state=loading|empty|success|failed|warning`，仅用于 M1 审核；M2 由 Mock Adapter 驱动。

## 6. 导航结构

### 6.1 登录前

- 左：品牌“研序 / ScholarFlow”。
- 右：登录、注册。
- 不展示产品价格、会员权益或购买入口。

### 6.2 登录后全局侧栏

固定顺序：

1. 项目工作台；
2. 我的项目；
3. 文献库；
4. AI 任务；
5. 最近项目；
6. 账户菜单。

“新建项目”作为顶部主要操作，始终指向 `/projects/new`，不默认打开 Idea 弹窗。

### 6.3 项目上下文导航

进入项目后，顶部面包屑显示：

`我的项目 / 项目名 / 当前页面或章节`

项目内导航顺序：

1. 概览；
2. 诊断卡；
3. 论文目录；
4. 编辑器；
5. 材料；
6. 引用证据。

AI 任务仍属于全局任务中心；在项目页通过项目筛选查看。DOCX 导出是编辑器顶部操作，不作为全局侧栏项。

### 6.4 窄屏

- 全局侧栏折叠为顶部品牌栏与菜单抽屉。
- 项目导航改为水平滚动标签或项目菜单。
- 编辑器不强行同时挤压三栏：默认正文，目录和章节助手分别通过抽屉打开。
- “诊断卡未确认”阻断条固定在编辑器内容顶部，不能因折叠而消失。
- 保存版本和导出 DOCX 保持可达；次要格式按钮允许收进更多菜单。

## 7. 五种项目创建方式

五种入口共享“项目基础信息 → 对应输入 / 上传 → 文件队列 → 确认并生成诊断卡草稿”的框架，但字段、提示和输出不同。

| 创建方式 | 主要输入 | M1 页面重点 | M2 完成态 | 安全与真实性提示 |
|---|---|---|---|---|
| 从一个 Idea 开始 | 主题、对象、背景、初步问题、论文类型、目标语言、字数、截止日期、引用格式、其他要求 | 表单层级、必填与缺失提示 | 创建项目并进入诊断卡草稿 | 不直接生成完整论文 |
| 导入已有初稿 | DOCX、PDF、TXT 或粘贴正文 | 上传 / 粘贴切换、原稿保护说明 | 识别章节并建立不可覆盖的原始版本 | AI 只创建新版本 |
| 上传论文要求 | 课程题目、评分标准、学校模板、导师意见、投稿要求或文字说明 | 要求类型、来源、约束预览 | 形成结构化约束并进入诊断卡 | 解析结果需用户确认 |
| 导入文献与同水平参考论文 | PDF、DOCX 笔记、BibTeX、RIS、DOI / TXT 列表、多篇参考论文 | “文献”与“参考论文”用途区分 | 文献矩阵或目标写作特征卡预览 | 只分析规范，不复制表达；无外部数据库验证承诺 |
| 上传数据或研究材料 | XLSX、CSV、TXT、问卷、访谈、实验数据、语料、编码表、图片 | 文件类型、隐私提醒、“不执行代码”提示 | 字段 / 变量 / 缺失值概览及方法建议 | 不自动运行代码，不把建议写成已完成结果 |

共用规则：

- M1 上传队列展示静态 Mock 状态样例。
- M2 队列包含等待、处理中、成功、失败和已取消；允许返回编辑、保存草稿和删除队列项。
- 文件支持提示统一使用：PDF、DOCX、XLSX、CSV、TXT、JPG、JPEG、PNG、BibTeX、RIS。
- 不承诺复杂 OCR、加密 PDF、损坏文件恢复、复杂公式或多栏版式完全还原。
- 任何入口创建后都先进入可修改的诊断卡草稿，不直接进入正式章节写作。

## 8. 三栏编辑器

### 8.1 顶部项目栏

- 面包屑：项目名 / 当前章节。
- 章节状态、字数、当前版本、保存状态。
- 操作：保存版本、版本历史、导出 DOCX。
- 若有未保存修改，离开章节或导出前显示确认。
- 不出现 PDF、Markdown、分享或协作按钮。

### 8.2 左栏：结构与材料

两个页签：

1. `论文目录`
   - 章节层级；
   - 当前章节；
   - 章节状态：空、草稿、待确认、已确认、需修改；
   - 缺证据或阻断标记。
2. `项目材料`
   - 本节已授权材料；
   - 文件类型、名称和处理状态；
   - 添加 / 更换本次允许读取的材料；
   - 文献和其他材料清楚区分。

左栏不表示“AI 可读取整个项目”。只有用户勾选并确认的材料进入本次 SkillContext。

### 8.3 中栏：章节正文与版本

- 章节标题、正文编辑区、基础格式和字数。
- 当前版本标签与来源：原稿、人工保存、AI 生成、AI 修改、恢复副本。
- 原始版本只读且有“不可覆盖”标识。
- 正文中的证据标记可打开右栏对应证据卡。
- 检查报告以批注 / 侧栏结果呈现，未经用户操作不修改正文。
- 版本历史抽屉展示时间、来源、模型和说明。
- 版本比较使用双栏或差异视图；恢复按钮明确“创建恢复副本”。

### 8.4 右栏：六个产品级 Skill、材料、证据与任务

固定展示六个产品级 Skill：

1. 项目诊断与提纲；
2. 文献总结与文献矩阵；
3. 通用章节写作；
4. 通用修改；
5. 一致性检查；
6. 引用与证据检查。

选择 Skill 后按顺序显示：

1. 本次操作说明；
2. 前置门：诊断卡状态；
3. 材料授权：用户明确勾选；
4. 具体要求输入；
5. 将使用的模型标签；
6. “运行并创建新版本”或“运行检查”按钮；
7. 任务状态；
8. 结果、缺失信息、警告和下一步。

交互门控：

- 未确认诊断卡：禁用“通用章节写作”，展示“返回诊断卡确认”。
- 未选择材料：需材料的 Skill 禁止提交，提示选择范围。
- 一致性检查、引用与证据检查：按钮为“运行检查”，结果为报告，不承诺创建正文版本。
- 主模型失败：M2 只展示“是否使用 DeepSeek 备用模型重试”的 Mock 决策；不得静默切换。
- 备用模型重试：明确新任务、新版本、结果分别保存。

### 8.5 引用证据卡

证据卡至少显示：

- 论断短句；
- 来源文件；
- 页码或段落；
- 短原文片段；
- 支持等级：直接支持、间接支持、无法确认；
- 核验范围：仅基于用户上传原文；
- 无法确认时的显著警告。

不能仅用绿色对勾表示“真实”。成功解析、存在来源和外部数据库验证是三个不同概念。

## 9. 页面状态系统

所有主要页面和关键区域都必须具备以下五种状态。M1 用状态组件和样例展示视觉语义，M2 接入 Mock 点击流程。

| 状态 | 视觉与文案 | 必须提供的操作 | 禁止表达 |
|---|---|---|---|
| 加载 `loading` | Skeleton、当前正在读取的对象、预计下一步 | 允许取消的任务显示“取消” | 假进度百分比、未经证实的“即将完成” |
| 空 `empty` | 说明为什么为空、完成该区价值 | 单一明确 CTA，如“上传第一篇文献” | 把空白页当空状态 |
| 成功 `success` | 说明完成了什么、结果属于 Mock 还是真实 | 查看结果、继续下一步 | 将“解析成功”写成“引用已核验” |
| 失败 `failed` | 用户可理解原因、失败阶段、处理器 / 模型、是否可重试 | 重试、换文件、返回编辑；模型失败可选择备用模型 | 静默失败、静默切换模型 |
| 警告 `warning` | 缺失信息、未确认诊断、无法验证引用、未保存修改 | 去补充、去确认、查看来源、仍可继续时说明后果 | 用普通灰字弱化高风险警告 |

### 9.1 文件处理状态

- 等待处理：文件已加入队列；
- 正在处理：显示处理器和取消入口；
- 处理成功：只表示内容可供系统读取；
- 处理失败：显示失败阶段、原因和可重试性；
- 已取消：保留记录，可重新加入队列。

### 9.2 AI 任务状态

- 等待执行；
- 正在执行；
- 执行成功；
- 执行失败；
- 已取消。

成功生成或修改必须指向新版本；失败必须展示实际使用的模型。M1 的任务数据均标记 Mock。

### 9.3 诊断卡状态

- 未开始；
- 草稿；
- 等待确认；
- 已确认；
- 材料变化后需更新。

“草稿 / 等待确认”和“已确认”必须在状态标签、主按钮和编辑器门控上同时体现，不能只改变一处颜色。

### 9.4 证据状态

- 直接支持：来源与论断直接对应；
- 间接支持：仅能支持部分或背景；
- 无法确认：没有可回到的上传原文位置，使用警告样式。

## 10. M1 与 M2 的交付边界

### 10.1 M1：视觉基线与核心骨架

M1 必须做到：

- 登录、注册和登录后导航框架；
- 项目工作台 / 项目列表；
- 五种创建方式选择及五个表单骨架；
- 上传队列视觉样例；
- 项目诊断卡草稿与确认态；
- 目录骨架；
- 三栏编辑器、六个产品级 Skill、材料授权与证据卡；
- 未确认诊断卡的写作阻断态；
- 加载、空、成功、失败、警告通用状态；
- 用户侧只显示导出 DOCX；
- 所有演示内容明确标记 Mock。

M1 不要求：

- 持久化登录或真实账号；
- 真实文件解析、上传存储或 OCR；
- 真实 AI / Skill 调用；
- 真实版本保存；
- 真实 DOCX 下载；
- 管理员四页完整原型；
- 完整连续点击闭环。

### 10.2 M2：完整前端可点击原型

只有用户明确批准 M1 后才能进入 M2。M2 在 Mock Adapter 上完成：

- 登录 / 注册到项目列表；
- 五种创建入口的分步流程；
- 上传队列的处理、成功、失败和取消；
- 诊断卡修改、确认、取消确认和需更新；
- 目录编辑、排序和章节状态；
- 编辑器章节切换、六 Skill、材料授权、任务状态；
- 新版本、版本比较和恢复副本；
- 引用证据来源定位与无法确认警告；
- DOCX 导出前检查；
- 简易管理员四页；
- 桌面与窄屏的连续可点击演示。

M2 仍不接入正式数据库、真实文件解析、真实模型或生产部署。

## 12. M1 视觉与交互验收检查

1. 用户能在首屏识别项目当前阶段、风险和下一步。
2. 五种创建入口名称、用途和材料类型不会混淆。
3. 诊断卡草稿、已确认和需更新有明显区别。
4. 诊断卡未确认时，正式章节写作按钮不可用。
5. 三栏分别承担结构 / 正文 / Skill 与证据，不重复堆叠。
6. 右栏展示完整的六个产品级 Skill，不出现内部 Skill 名称。
7. 用户能看见本次 Skill 会读取哪些材料，并可修改选择。
8. 原稿不可覆盖、新操作创建版本的规则在关键动作前可见。
9. 引用证据可见来源、位置、原文片段和支持等级。
10. 无法验证的引用采用显著警告，而不是普通辅助文字。
11. 用户侧导出只出现 DOCX。
12. 不出现会员、支付、共享协作、AI 率、查重等伪入口。
13. 所有 Mock 数据与真实能力明确区分。
14. 桌面与窄屏核心内容可达，无控制台错误。

## 13. 当前 UX 风险

| 风险 | 等级 | 处理建议 |
|---|---|---|
| 当前单页 `View` 状态与冻结路由不一致 | 高 | M1 将页面拆为真实路由，保留可复用组件 |
| 当前可绕过诊断确认直接进入编辑器 | 高 | 路由守卫与编辑器阻断态同时处理 |
| “已验证原文”易被理解为外部数据库验证 | 高 | 全局替换为“已上传并解析 / 可回到上传原文核对” |
| 当前右栏四个快捷动作与六产品级 Skill 不一致 | 高 | M1 统一为六 Skill，快捷操作下沉 |
| 通用创建弹窗无法体现五种材料差异 | 中 | 五个创建路由分别定义输入和提示 |
| 窄屏当前把目录直接隐藏、助手整段下移 | 中 | M1 改为目录 / 助手抽屉，正文优先 |
| Mock 与真实能力未持续标识 | 高 | 页面级 Mock 横幅 + 结果级 Mock 标签 |
| M1 若提前实现管理员、版本逻辑或 AI 调用会扩大范围 | 中 | 管理员完整原型留到 M2；真实能力留到后续里程碑 |

## 14. 冻结结论

M0 后冻结以下 UX 项，后续改变必须登记 `docs/change-log.md`：

- 用户端与管理员端信息架构；
- 本文第 5 节路由命名；
- 五种项目创建方式及其职责；
- 三栏编辑器职责；
- 六个产品级 Skill 名称；
- 诊断卡确认门和材料授权门；
- 加载、空、成功、失败、警告状态语义；
- DOCX 单一用户导出入口；
- M1 / M2 交付边界；
- M1 审核截图清单；
- 全部排除功能不得出现入口。

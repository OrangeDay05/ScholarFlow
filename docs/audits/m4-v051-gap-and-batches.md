## 3. 数据库现场

- 技术：Cloudflare D1（SQLite）+ Drizzle ORM。
- Schema：`db/schema.ts`。
- 已有迁移：`drizzle/0000_swift_blue_shield.sql`；工作区另有未提交 `0001_vengeful_tigra.sql`。
- 本地 D1 当前含 42 张业务表和演示/测试数据；没有生产数据证据。
- `d1_migrations` 存在但为 0 条，实际表与台账不一致。
- 0001 只有 `CREATE TABLE/INDEX`，没有删除或改列，但不能对当前库盲目重复执行。
- 迁移策略：先在全新隔离库按 0000→后续迁移完整验证；现有库只读预检表、列、索引与台账，确认等价后再显式协调。禁止重建或删除现有库。

## 4. 隐私和分析保真

处理策略必须分别记录直接标识符、间接标识符、敏感属性、研究必要变量、普通研究正文、伦理/保密限制、版权/合同限制。任何变换都不得静默删除实验条件、改变样本量、合并参与者、打乱时序、删除必要变量、改变数值精度或破坏说话人关系；发生上述风险时应阻断外传或要求用户确认，不得伪称“已安全脱敏”。

## 5. PPT 场景

数据契约至少覆盖课程论文汇报、课堂展示、文献汇报、小组汇报、期末展示、研究计划、开题答辩、中期答辩、毕业答辩、组会、会议汇报、论文分享和投稿展示。可用性只由材料就绪度与内容真实性决定，不使用学历作为门槛。

# 论文 AI 系统 V0.3 产品范围基线

文档状态：M0 需求基线，待根 Agent 固化

适用版本：V0.3 简易通版

更新时间：2026-07-24

## 1. 文档用途与依据

本文定义 V0.3 的页面范围、用户流程、六个产品级 Skill 的前端展示方式和明确不做项，作为 M1/M2 前端及后续业务实现的范围边界。

依据优先级：

1. `论文AI系统需求说明_V0.3_简易通版.md`：产品范围和最终验收的唯一主依据。
2. `给系统开发Agent的Skill集成说明.md`：只补充 Skill 映射、输入输出门和工程约束。
3. `论文AI系统_Codex阶段门控项目管理开发指令_V1.0.txt`：规定里程碑、审核门和验证方式。

发生差异时按以上顺序处理。不得将“本机已安装或自检通过的 Skill”写成“网页产品已接入或功能已实现”。

## 2. V0.3 产品目标

V0.3 是面向中文和英文研究写作项目的通用论文 AI 工作台，核心形态为：

> 论文项目管理 + 材料解析 + 项目诊断 + 章节工作流 + 文献知识库 + 引用证据 + 版本管理 + DOCX 导出

系统不限定论文类型或学科。用户通过填写要求和上传材料说明自己的具体场景；产品不承诺 V0.3 对所有学科具有专用分析能力。

核心业务原则：

- 先理解项目要求，再生成论文内容。
- 诊断卡是后续任务的上下文门；用户修改并确认前，不得进行正式章节写作。
- 用户必须显式选择每次任务可读取的材料。
- 用户材料优先于 Skill 示例和通用规则。
- AI 生成、修改、恢复旧版和切换模型都创建新版本，绝不覆盖原稿。
- 重要论断尽量绑定用户实际上传且解析成功的材料和原文位置。
- 必须区分材料事实、AI 归纳或推断、缺失信息和无法验证内容。
- 没有数据时不生成虚构研究结果；没有可靠来源时不生成虚构文献事实。
- 用户侧只提供 DOCX 导出。

## 3. 当前阶段边界

| 阶段 | 本阶段可实现 | 本阶段不得声称 |
|---|---|---|
| M0 | 需求、范围、信息架构、Mock 契约和工程基线文档 | 任一业务能力已实现 |
| M1 | 六个核心页面的视觉骨架和 Mock 展示 | 真实注册、上传解析、AI、版本、证据或导出已接入 |
| M2 | 基于 Mock 数据的完整可点击原型 | 数据已持久化、文件已真实解析、模型已真实调用 |
| M3–M7 | 按阶段门逐步接入持久化、后端、解析、模型、Skill、证据和 DOCX | 未经当前阶段测试的后续能力已完成 |
| M8 | 仅在用户明确要求后生产部署 | 本地预览或已有项目配置等同于已上线 |

所有 M1/M2 页面上的模拟结果、模拟解析、模拟 AI 任务和模拟管理员数据必须显著标记为“演示数据”或“Mock”。

## 4. 用户与权限范围

### 4.1 普通用户

普通用户只能访问自己的项目，可以：

- 使用手机号或邮箱和密码注册、登录、退出；
- 创建、编辑、归档和删除自己的项目；
- 使用五种方式创建项目；
- 上传和管理本项目材料；
- 修改并确认诊断卡及论文目录；
- 使用六个产品级 Skill；
- 保存、比较和恢复章节版本；
- 查看引用证据及无法验证警告；
- 导出用户选择章节的 DOCX。

V0.3 不允许游客、不允许共享账号、不允许共享项目和多人协作。

### 4.2 简易管理员

管理员只允许进入四类管理页面：

1. 用户管理；
2. 项目与文件；
3. AI 任务；
4. 模型与 Skill。

管理员可查看必要状态、错误和日志，可冻结或解冻账号、启停模型和 Skill。管理员不进入用户论文的协作流程，也不具备订单、会员、营收或客服运营功能。

### 5.1 M1 必须真实渲染的六个核心页面

1. 登录页；
2. 项目列表页；
3. 五种创建方式选择页；
4. Idea 创建表单；
5. 项目诊断卡；
6. 三栏论文编辑器。

验收时必须使用真实浏览器访问，而不是以设计稿或代码截图代替。

### 5.2 通用页面状态

所有涉及数据、上传、AI 任务或异步动作的页面/组件都要设计：

- 初始状态；
- 空状态；
- 加载或等待状态；
- 执行中状态；
- 成功状态；
- 失败状态；
- 警告状态；
- 已取消状态（适用于文件和 AI 任务）。

失败状态至少显示用户可理解的原因和可用下一步。Mock 阶段不得伪装成真实处理结果。

## 6. 核心用户流程

### 6.1 主流程

注册或登录 → 项目列表 → 选择五种方式之一创建项目 → 填写或上传材料 → 查看材料处理状态 → 生成诊断卡草稿 → 用户修改并确认诊断卡 → 生成或确认论文目录 → 进入三栏编辑器 → 选择章节和一个产品级 Skill → 显式选择本次允许读取的材料 → 查看缺口或启动任务 → 获得新版本或检查报告 → 查看版本、引用证据和警告 → 执行导出前检查 → 导出 DOCX

### 6.2 五种创建分支

#### A. 从一个 Idea 开始

输入项目基本信息 → 生成诊断卡草稿 → 用户补齐缺失项并确认 → 推荐论文结构。

停止条件：研究对象、论文类型、目标语言或预期交付物等关键输入缺失且会改变结构时，只提示补充，不直接生成完整论文。

#### B. 导入已有初稿

上传 DOCX/PDF/TXT 或粘贴正文 → 解析状态 → 识别章节和主要要素 → 原稿保存为不可覆盖初始版本 → 诊断卡与逐章修改建议。

#### C. 上传要求

上传或填写课程、学校、导师、期刊/会议要求 → 解析为结构化约束 → 更新诊断卡草稿 → 用户确认 → 后续任务读取已确认约束。

#### D. 导入文献或同水平参考论文

上传 PDF、DOCX 笔记、BibTeX、RIS、DOI/TXT 列表或参考论文 → 解析状态 → 文献事实字段/矩阵 → 目标写作特征卡。

目标写作特征卡只分析结构、论证、引用密度、语气和呈现规范，不复制参考论文原文表达。仅有 DOI 或参考文献列表时，如未接外部合法检索，不得显示“原文已核对”。

#### E. 上传数据或研究材料

上传 XLSX/CSV/TXT/图片等 → 显示结构、字段、变量、样例和缺失值概览 → 提示可采用的方法和结果章节信息缺口。

V0.3 只给分析建议，不自动运行用户或 AI 生成的代码，不得将计划或建议显示成已完成的研究结果。

### 6.3 关键阻断与分支

- 诊断卡未确认：章节写作按钮禁用或操作被明确阻断，并提供“去确认诊断卡”入口。
- 未选择材料：需要材料的任务不能启动，并提示用户勾选可读材料。
- 缺少会改变判断的材料：任务返回缺口清单，不以常识补成项目事实。
- 主模型失败：展示失败模型和原因，由用户决定是否使用 DeepSeek 重试；不得静默切换。
- 备用模型重试：创建新任务和新版本，保留主模型失败记录和已有结果。
- 检查任务：只生成报告和警告，不静默改写正文。
- 恢复旧版本：创建一个新的恢复版本，原历史不被改写。
- 无法验证引用：显著标为“无法确认”，不得显示成已验证。

## 7. 六个产品级 Skill 的前端展示

### 7.1 展示总则

- 普通用户界面只显示以下六个产品级名称，不显示内部 Skill 包或几十个子 Skill 名称。
- M1/M2 只显示骨架或 Mock 任务时，必须标注“演示”；不能因相关 Skill 已安装就宣称已接入。
- 每次任务只选一个产品级 Skill；内部只能有一个主入口，后续模块按明确顺序执行。
- 每个任务面板统一显示：用途、作用章节、必需输入、可选材料、材料选择、目标语言/字数、任务状态、输出类型、警告、模型记录和下一步。
- 正文生成或修改成功必须关联新版本；检查类输出关联报告，不直接改正文。

### 7.2 前端卡片与任务结果

| 产品级 Skill | 用户看到的用途 | 启动前门槛 | 主要输出 | 前端必须显示 |
|---|---|---|---|---|
| 项目诊断与提纲 | 理解要求、生成/更新诊断卡和提纲 | 至少有项目输入；关键字段缺失时先补充 | 诊断卡草稿、提纲、缺口和下一步 | 草稿/已确认状态、可编辑字段、缺失项、风险、确认按钮；不得出现“一键生成全文” |
| 文献总结与文献矩阵 | 总结选中文献并形成统一矩阵 | 用户显式选择已上传材料；需原文证据时材料须解析成功 | 单篇总结、文献矩阵、证据位置 | 原文事实、AI 归纳、缺失项分区；文件、页码/段落、短原文；无法核对警告 |
| 通用章节写作 | 生成摘要、引言、综述、方法、讨论等章节的新版本 | 诊断卡已确认；已选章节和材料；所需数据/前置章节足够 | 章节新版本或缺口清单 | 目标章节、材料清单、目标语言/字数、版本编号、生成来源、数据不足警告 |
| 通用修改 | 润色、扩写、精简、翻译、衔接、术语统一和按意见修改 | 已选择现有章节/版本和修改方式 | 修改后的新版本、修改说明 | 修改前版本、操作类型、新版本编号、差异入口；永不覆盖原文 |
| 一致性检查 | 检查问题—方法—结果—讨论—结论、术语和证据链 | 已选择检查范围；必要章节可用 | 检查报告、问题等级和建议 | 检查范围、问题等级、对应章节/位置、建议；明确“检查不会自动改正文” |
| 引用与证据检查 | 检查正文引用、参考文献和上传原文的对应关系 | 已选正文范围和已解析文献 | 证据报告、绑定关系和警告 | 来源文件、页码/段落、短原文、直接/间接/无法确认；外部数据库未验证声明 |

## 8. 文件与任务范围

### 8.1 支持的上传类型

- PDF；
- DOCX；
- XLSX；
- CSV；
- TXT；
- JPG；
- JPEG；
- PNG；
- BibTeX；
- RIS。

“支持上传”必须拆分显示为上传校验、处理状态和真实可实现的解析结果。无法解析、不支持、加密或损坏文件要进入真实失败状态，不能以空白成功代替。

V0.3 不承诺复杂扫描件高准确率 OCR、加密 PDF 解析、损坏文件恢复、复杂公式/脚注/多栏版式完全还原、旧 DOC/XLS 完整兼容。

### 8.2 任务状态

文件处理和 AI 任务至少覆盖：

- 等待执行；
- 正在执行；
- 执行成功；
- 执行失败；
- 已取消。

失败记录至少包含失败阶段、错误类型、用户提示、实际模型或处理器以及是否允许重试。

| 手机号/邮箱换绑 | 不显示换绑流程 |
| 项目共享和多人协作 | 不显示邀请、成员、共享链接、评论协作 |
| 多人共用账号 | 不提供子账号或共享登录能力 |
| AI 写作风险检测 | 不显示 AI 率、风险分数或检测入口 |

- “已上传原文可核对”；
- “仅有用户提供的元数据，尚未核对原文”；
- “外部数据库未验证”。

## 10. 完成定义

范围内功能只有在对应里程碑同时具备以下证据时才能标记为完成：

1. 实现与当前阶段一致，不把 Mock 当成真实能力；
2. 通过 `docs/acceptance-matrix.md` 中对应检查；

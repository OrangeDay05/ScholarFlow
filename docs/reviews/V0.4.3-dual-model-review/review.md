# V0.4.3 双模型生成与独立审阅 Mock 审核报告

更新时间：2026-07-27
状态：WAITING_FOR_REVIEW

## 1. 本轮目标

在已批准的 M2 三栏写作工作台内，以增量、可关闭的前端 Mock 增加“双模型生成与独立审阅”流程。生成模型与审阅模型相互独立；审阅只生成报告，用户决定是否采纳，任何生成、修订和恢复都追加新版本。

本轮没有重写 M2 编辑器，没有修改正式 Schema、执行迁移、接入真实模型或新增 Skill，也没有创建或执行生产部署。

## 2. 已完成能力

- AI 任务配置增加“不复核、标准复核、严格复核”三种选择，分别对应快速、标准和严格流程。
- 执行前显示生成模型、审阅模型、供应商、Skill、版本、预计调用次数、预计耗时和本次允许读取的材料。
- 默认用 OpenAI GPT-5.2 Mock 生成、DeepSeek Reasoner Mock 独立审阅；可切换审阅模型重新审阅。
- 审阅上下文明确列出用户原始要求、已确认诊断卡、授权材料、生成版本和证据绑定。
- 明确约束审阅模型不得只凭模型知识判断文献是否支持论断，且审阅报告不覆盖正文。
- 展示统一结论：`PASSED`、`PASSED_WITH_WARNINGS`、`REVISION_REQUIRED`、`BLOCKED`、`REVIEW_FAILED`。
- 审阅报告覆盖要求符合度、项目约束、事实、引用证据、逻辑、研究问题与方法、结果结论边界、过度声明、缺失信息、学术表达和用户原意。
- 支持查看问题、按严重等级筛选、选择部分意见、接受原版本、填写理由忽略、生成修订版本和更换审阅模型。
- 严格流程最多追加一次自动修订和一次最终验证，不建立无限自动循环。
- 审阅失败时保留生成版本，并明确显示 `REVIEW_FAILED`，不会标记为通过。
- `NEXT_PUBLIC_DUAL_MODEL_REVIEW_MOCK=false` 或 `0` 时关闭全部新增入口，恢复原 M2 任务界面。

## 3. 演示路由

- 核心编辑器：`/projects/demo/editor?section=introduction`
- 右栏入口：AI 工作台 → 选择可执行写作/修改 Skill → 任务配置 → `AI 复核`

## 4. 核心演示流程

严格复核的 Mock 主流程为：

```text
生成任务
→ 章节版本 V4
→ 独立审阅报告 R4（REVISION_REQUIRED，不修改 V4）
→ 用户选择 4 / 5 条问题
→ 章节版本 V5
→ 最终验证报告 F5（PASSED_WITH_WARNINGS）
```

用户也可以接受 V4、填写理由忽略问题、更换审阅模型重新生成审阅报告，或模拟审阅失败。以上决定只改变本次 Mock 工作流状态，不覆盖旧版本。

## 8. Mock 与真实能力边界

本轮真实完成的是前端状态、交互、视觉、响应式与可测试的 Mock 契约。以下均未实现：

- OpenAI、DeepSeek 或其他供应商的真实调用；
- 真实任务队列、调用计费、重试和服务商故障切换；
- 审阅报告、问题、用户决定、父子任务和验证结果的数据库持久化；
- 正式 Schema 变更或迁移；
- 真实 Skill 执行；
- 真实文献数据库验证；
- 生产部署。

页面中的模型名、预计耗时、调用次数和审阅结果均为审核交互设计使用的演示数据，不代表已签约或已接入供应商。

## 9. 已知问题

- 刷新页面会重置本轮双模型复核 Mock 状态。
- 问题选择和忽略理由目前只存在于页面内存。
- Mock 审阅内容用于验证界面和规则，不能作为真实论文审阅结论。
- 已有 M3 D1 基础能力保持原状；本轮没有把双模型新字段写入数据库。

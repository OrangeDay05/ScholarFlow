## 五、单次真实调用的准确操作

1. 打开 `http://localhost:3000/settings/models`，选择本次测试项目。
2. Agent Role 选择“修订 Agent（REVISER）”；Provider 选择 DeepSeek；明确选择一个页面提供的有效模型、Thinking Mode、模型实际支持的 Reasoning Effort、最大输出和正数预算。
3. 不配置 fallback；不要点击“确认并同步目录”或“确认并测试当前组合”。只点击“保存当前角色配置”。
4. 打开 `http://localhost:3000/projects/{projectId}/editor`，选择有正式基础版本的章节。
5. 在“AI 工具”点击“通用修改”。确认页面自动切换到“AI 对话”，Prompt、当前章节、基础版本和授权材料均正确。
6. 可使用以下无敏感测试目标：

   > 只修改当前测试文本的第一段：删除重复表达，统一核心术语，并弱化过度结论。不要添加新文献，不要修改第二段，不要改变原有研究主题。

7. 讨论后点击“整理为操作提案”。先不要确认，刷新页面；确认提案仍存在，而且没有 AITask 或 Provider 调用。
8. 明确确认提案，核对执行框中显示 REVISER、DeepSeek、所选模型、Thinking Mode、Reasoning Effort、最大输出、预计调用 1 次、预算及材料范围。
9. 只点击一次“确认配置并执行 1 次”。按钮进入忙碌或任务结果出现后不要重复点击。
10. 候选出现后核对基础版本 ID、候选版本 ID 和新增/删除/替换差异。先点“拒绝候选”，刷新确认原版本未变；随后对同一候选点“采用候选”，不得再次执行任务。
11. 重启本地服务并刷新，确认会话、提案、任务、候选、差异和采用状态仍存在。

完成第 7 步后先通知 Codex；Codex将只读核对 Provider 调用仍为 0。完成第 9 步后再次通知 Codex；Codex将核对恰好新增 1 条 Provider 运行记录。不要自行第二次点击执行。

## 六、错误场景

- 未配置 Key：显示需要配置，不调用 Provider。
- Key 错误、超时、额度不足、模型不可用：显示统一安全错误，不返回 Key、响应原文或堆栈。
- 用户取消、预算不足：不追加调用，不自动恢复或切换模型。
- 材料丢失、基础版本变化：阻断执行并要求重新确认。
- 候选生成失败：任务不得标记成功，已完成步骤和原版本保留。
